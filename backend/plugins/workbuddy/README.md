# WorkBuddy 国内版 DeepSeek 插件

独立进程插件，能力 `upstream.chat_completions.v1`。需要本分支的宿主扩展，不能安装到仅支持 OpenAI OAuth 的旧宿主。

## 使用

1. 用本仓库 Go 工具链构建 `./plugins/workbuddy`；Linux 生产目标使用 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64`。
2. 使用 `ops/plugins/package_workbuddy.py` 打包签名。私钥置于仓库外或被忽略的私有目录，宿主只配置信任公钥。禁止打开全局未签名安装。
3. 上传并启用插件，配置页添加账号。点击宿主显示的官方 HTTPS 授权链接，完成登录后检查结果。
4. 创建并绑定宿主账号。账号初始无分组，管理员在账号管理分配 DeepSeek 分组、并发、价格与倍率；插件不会改价。
5. 使用受限测试 Key 验证真实流式、工具、用量、账单，再单独批准生产发布。

授权会话和账号凭据存入宿主加密配置；跨实例轮询与刷新由数据库行锁串行化。账号 ID 与身份引用一一绑定，绑定不可静默改写。重新授权必须使用原账号。解除授权删除登录材料，保留绑定和历史账单；重新登录同一账号可恢复身份。解除宿主绑定则要求先在账号管理停用该账号，仅删除当前绑定，不删除账号或历史记录。

`config.load` 对供应商插件返回空对象，普通 `config.save` 禁用；凭据仅通过私有授权 RPC 更新。插件 UI 只读取脱敏状态。每个请求无共享上游对话状态，原样保留标准 CC 历史、工具与用量。

## 兼容与限制

初始协议参考固定于 `d73db9816ffa54ea9bca1c1e0b68612abeac8e8c`，不自动执行上游更新。不导入桌面文件、不包装第三方设备 SDK、不生成设备伪装信息、不修改用户提示词以通过渠道检查。HTTP 请求使用独立客户端标识；上游是否接受 Linux 服务器请求必须由真实账号验收。

首期只支持标准 Chat Completions 的 JSON/SSE、文本与函数工具。实际模型白名单从国内版目录读取；图片、音频、后台任务、独立搜索和持久化 Responses 会话不在首期范围。其他外部协议由宿主转换，不能转换的请求明确失败。

目录测试不调用推理、不代表推理可用。缺失用量不补造，计费仍由宿主处理。当前实现不保证上游非公开接口稳定性；认证、限流、额度和风控错误应在真实验收报告中分别记录。

## 回退

先停用插件并等待在途请求结束，再恢复上一签名包和已验收配置。保留 `258_plugin_provider_accounts.sql` 和历史绑定；回退应用前先确认旧版本不会调度 `type=plugin` 账号，必要时先将这些账号停调度。不得删除已应用迁移或关闭迁移校验。
